## B. Numerical, design and inference issues (documented in v0.17; open unless stated)
1. **LoRA deltas are rounded when merged into bf16 weights.** `interventions/cell.py:197` (`apply_hf`)
   and `:292–297` (`apply_tl`) do `w.add_(d.to(w.dtype))` on bf16 weights. Against the real weights,
   31–43 % of non-zero ΔW entries round to zero; the relative L2 error of the applied delta is 0.25
   (circuit_s0), 0.26 (random_s0), 0.32 (circuit_joint_s0), 0.37 (unrestricted_s0), 0.25
   (perturb_circuit_s0), so it depends on the condition. MEMIT deltas lose 0.3–4 % (circuit 0.003,
   unrestricted 0.032, random 0.040). English edited-fact efficacy, merged vs exact (fp32 forward hook,
   unmerged), is identical for 4 of 5 cells; random_s0 is 0.617 merged vs 0.583 exact. Collateral, L4
   and every B2 LoRA number were not re-measured, and the reported |Δθ| is the unrounded norm. Open:
   apply LoRA as an fp32 hook (or merge in fp32) and re-audit the LoRA cells.
2. **`n_trainable` counts adapter entries, not trained entries** (`interventions/lora.py:194`,
   `sum(p.numel() for p in params)`). Masked q/k/v `lora_B` rows and `o_proj` `lora_A` columns stay
   exactly 0 but are counted (unrestricted, which has no masks, has nonzero = entries, so the nonzero
   count is the trained count). Trained vs reported: circuit 2.82–2.96 M vs 3.49–3.70 M; random
   3.24–3.51 M vs 4.13–4.55 M; inverse 3.03–3.23 M vs 3.81–4.13 M; Taylor 2.41 M vs 2.85 M;
   circuit_joint 7.82–8.20 M vs 8.39–8.81 M; random_joint 8.24–8.62 M vs 9.03–9.45 M; unrestricted
   15.11 M both. Unrestricted / circuit is 5.1–5.4×, not 4.1–4.3×; random has ~18 % more trained
   entries than circuit, not ~25 %; circuit_joint uses 53 %, not 56 %, of the unrestricted count. The
   capacity reading survives (efficacy Spearman 0.861 on trained entries). Deliverables corrected; the
   CSV column and `lora.py`'s docstring ("parameter count (size-matched by construction)") are open.
3. **"Head-masked" LoRA is KV-group-masked for k/v.** `lora.py:74–85`: for a selected head the
   k_proj / v_proj `lora_B` rows of its whole GQA group train (4 query heads per KV head). The 58 heads
   of circuit_s0 / s1 / s2 put k/v adapters under 144 / 148 / 152 heads; random_s0's 58 heads under 208,
   because random heads spread over more groups (part of why random has more trained entries). The code
   docstring says so; the deliverables did not. Now stated in report §5 and technical report §1, §4.
4. **The fact circuit is discovered on a different relation mix than the facts it edits.** The 64-pair
   discovery subsets (`.cache/task_subsets/b1_en_64_s{0,1,2}.csv`, drawn from `eap_known_en.csv`, itself
   58 % city → country) contain city → country 37 / 36 / 40, capital 14 / 8 / 9, continent 7 / 8 / 7,
   language 3 / 8 / 3, currency 0 / 1 / 3, head of state 3 / 3 / 1, head of government 0 / 0 / 1. The 180
   targets are 86 head of state, 51 head of government, 33 country, 5 capital, 4 language, 1 currency.
   "Confining the edit to the circuit" therefore means confining it to a circuit found mostly on
   city → country and capital recall. This extends audit-06's steering confound to every B1 H1 / H2 /
   H5 reading. Now in report §5; open as a design limitation.
5. **The statistical unit is three seeds.** p-values and "survives Holm" treat language × family pairs
   (L3) or bystanders (L4) inside a seed as independent. The A15 LoRA L3 advantage has per-seed
   differences −0.014 / −0.013 / −0.002; a paired t over 3 seeds gives p = 0.127 and the smallest
   possible two-sided sign-test p is 0.25. With 3 clusters (10 distinct resamples) the seed-cluster
   bootstrap is not a valid interval and can be narrower than the pair CI (B1 LoRA L4 circuit − random:
   pairs [−0.006, +0.031], clusters [+0.009, +0.025]; A15 LoRA L4 vs random_joint: pairs [−0.044,
   +0.007], clusters [−0.032, −0.003]), so "seed-cluster CI excludes 0" is not robustness evidence.
   `pairs_for` (`analyze.py:505`) pairs random draws 3 and 4 with the circuit cells of discovery seeds
   0 and 1, so those two circuit cells enter twice. Now stated in report §4.3, §5 and technical report
   §3, §6.
6. **The Holm family is mixed and H2's own rule is not met.** 8 of the 20 B1 Holm tests are post-hoc
   A15 tests (the technical report called the family "the registered H2 tests"). Pre-registered H2
   requires circuit < random *and* circuit < inverse; A15 LoRA L3 is null against inverse_joint
   (−0.0024 [−0.014, +0.009]), so "the study's one locality advantage" does not meet H2. Now stated.
7. **"Differences between noise-level values"** (report §4.4, §5). The same-data repeat floor is
   exactly 0 and every cell is attributed on the same 32 examples, so cell-vs-cell CAD differences are
   not measurement noise of the cell; the resample floor measures the base attribution's between-subset
   variation, and how a cell-vs-cell difference varies with the example set was never measured. The
   wording now says that. H3's "18/18 show no L4 advantage" is weak support for the gate, because the
   LoRA and steering bystander CADs stay 0.08–0.35 below the floor even at 64 / 10.
8. **The power check is mask- and task-dependent.** At 64 / 10 on the joint masks the unrestricted LoRA
   (+0.020 target, +0.044 language-ID) and Taylor-layer MEMIT (+0.035 target) are above the floor;
   the deliverables quoted only the per-type masks. "No real B1 intervention's target CAD exceeds its
   floor" holds for the 32 / 3 campaign only. The check used the built-in IOI task, not `ioi_fixed`.
   Now stated.
9. **Provenance.** This repo's git history holds the two skeleton commits of 2026-11-02 (00:40, 01:18);
   the sibling repos are not git repositories. Every manifest records `git_sha 416938a` with no dirty
   flag, audit manifests (`manifest_hf.json`) record no input or output hashes, so no artifact is tied
   to the code that produced it. The pre-registration freeze can be checked only against the local
   backup (done above, passes). Open: committing the code and timestamping a hash of the frozen
   pre-registration is the owner's decision.
