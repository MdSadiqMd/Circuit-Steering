## B. Pass 1: mathematics

1. **The 0.5 floor is a property of the metric span, not of the circuit, and its exact value is per task.**
   CircuitKIT's ratio is r = (m − c)/(cl − c) with m the metric of the evaluated model, cl clean, c corrupt.
   A model whose logit difference is driven to 0 scores r0 = −c/(cl − c), which equals 0.5 only if c = −cl.
   `checks/check_metric_span.py` measures cl and c on the pillar examples of every task (seed 0, same
   tokenisation and metric path as CircuitKIT):

   | task | clean | corrupt | r0 | c/cl |
   |---|---|---|---|---|
   | b1_en | 11.08 | −11.46 | 0.509 | −1.035 |
   | b1_hi / ar / fr / sw | 7.53 / 7.75 / 10.31 / 7.91 | −6.94 / −7.11 / −9.72 / −6.99 | 0.480 / 0.478 / 0.485 / 0.469 | −0.92 / −0.92 / −0.94 / −0.88 |
   | b2_en | 7.72 | −1.38 | 0.152 | −0.179 |
   | ioi | 2.45 | −0.06 | 0.024 | −0.024 |
   | langid_en | 6.75 | −6.46 | 0.489 | −0.956 |

   The zero-referenced ratio r' = m/cl = (r − r0)/(1 − r0) reads 1 = intact, 0 = behaviour gone, < 0 =
   inverted, and is the quantity the necessity numbers should be read in (`circuits.md` second table,
   columns `r0`, `nec0_*`; mean replacement, set ablated, rest kept):

   | task (seed) | r0 | per-type set ablated r → r' | random per-type sets r → r' | joint set ablated r → r' |
   |---|---|---|---|---|
   | b1_en (0/1/2) | 0.509 | 0.52 / 0.52 / 0.49 → +0.02 / +0.02 / −0.04 | 0.65 / 0.66 / 0.64 → +0.30 / +0.30 / +0.26 | 0.52 / 0.50 / 0.49 → +0.01 / −0.03 / −0.05 |
   | b1_hi · ar · fr · sw (0) | 0.47–0.49 | → +0.03 · +0.02 · +0.01 · −0.08 | → +0.18 · +0.07 · +0.24 · +0.12 | → +0.02 · −0.02 · −0.05 · +0.05 |

   Reading: ablating the per-type fact set removes the whole clean logit difference (r' within ±0.08 of
   0) while ablating 58 random heads + 4 random MLPs leaves 7–30 % of it; so the per-type fact set is
   necessary (the behaviour does not survive without it), and the v0.14 wording "slightly more
   necessary than chance" understated it. The refusal per-type set leaves 38–45 % of the refusal logit
   difference when ablated, random sets 22–29 %: not necessary. IOI per-type: 4–13 % left vs 25–39 %:   necessary. The patching (sufficiency) ratios are unaffected by this re-referencing because they are
   already relative to the corrupt run. *Fixed* in the table and the report; no number changes, the
   reading does.
2. **Every CircuitKIT ratio is resolved to about 0.002–0.006 of the clean–corrupt span.** Pillar 1
   returns the mean metric in the model dtype: for IOI seed 0 the patched mean is 221/256, clean 159/64,
   corrupt 89/512 (`checks/ioi_plateau_raw.json`), i.e. bf16 values with an 8-bit mantissa. The ratio
   resolution is 2^(⌊log2 m⌋ − 7)/(cl − c): 0.0028 (b1_en), 0.0021–0.0031 (other fact circuits), 0.0034
   (refusal), 0.0062 (IOI), 0.0024 (language-ID) (`checks/metric_span.json`). Differences of that size
   between two ratios are not differences. *Documented*; the report quotes ratios to two decimals, which
   is within resolution.
3. **CAD and the resample floor.** CAD(C) = Σ_{e∈E(C)} |s_e(θ) − s_e(θ′)| / Σ_{e∈E(C)} |s_e(θ)| is a
   relative L1 distance; the floor is the same quantity with θ′ = θ and a different example subset, so
   CAD − floor is a comparison of two L1 distances with the same denominator and no cancellation. The
   independent recomputation in the third audit (max |diff| 2.4e−7) stands; the pillar-set mask added
   by `audit/l4_pillarmask.py` is computed from the same kept edge matrices with the same function.
4. **Multiple comparisons.** `audit/analyze.py` now records a two-sided percentile-bootstrap p-value
   (2·min(P(Δ* ≤ 0), P(Δ* ≥ 0)), floor 1/2000) for every pre-registered H2 comparison and prints a Holm
   step-down count. B2 (12 tests): 12 have p < 0.05 uncorrected, 8 survive Holm; the four that do not
   are the two LoRA "advantages" (circuit − random L3 −0.0073, circuit − random L4 +0.0074), LoRA
   circuit − inverse L4 (+0.013) and MEMIT circuit − inverse L3 (+0.039). B1: see §E after the A15 cells
   join the count. The one B2 locality advantage the report mentions (LoRA L3, a 0.007 effect) therefore
   does not survive correction. *Fixed* (reported in `hypotheses_*.md` and the report).
5. **H4's per-cell Spearman takes four values.** Over three bystanders a Spearman is one of {−1, −0.5,
   +0.5, +1}; the mean over cells (+0.59 B1, +0.54 B2) is a mean of such values, and its bootstrap CI is
   a CI on the fraction of cells with agreeing ranks, not on a continuous correlation. The report's
   "consistent in direction, not established" reading is unchanged; the discreteness is now stated.
6. **The steering norm match.** S = sqrt(Σ_n ‖coeff·v_n‖²) is the Frobenius norm of the stacked
   per-node vectors; matching S across node sets of equal size matches the total injected energy, not the
   per-node norm (a set with one large vector and many small ones matches a set of equal vectors). A15's
   joint cells are matched to the same S (|Δ| 8.65 at 0.5×) as every other B1 steering cell.

## C. Pass 2: software and numerics

1. **IOI plateau (third audit C16) explained.** `checks/check_ioi_plateau.py` rebuilds the 1 % and 2 %
   graphs for seeds 0 and 1: the 2 % set is a strict superset (7 → 13 nodes, 105/119 → 429 edges) and
   all six added nodes have in-graph paths to the logits (no connectivity artefact). Adding each node
   alone changes patching by −0.019 to +0.015 (seed 0) and −0.034 to +0.026 (seed 1), but all six
   together reproduce the 1 % value exactly, on a fresh run, because the six effects net to less than one
   bf16 quantum of the mean metric (B.2) on both seeds. Non-additive, weak, measured at coarse
   resolution: not a bug in node selection. The 1 % zero-ablation overshoot (3.7) is the ratio of a
   coarse metric with a corrupt value near 0 (c = 0.17 on the curve examples; r0 = 0.02), where small
   absolute metric changes are large ratios. *Fixed in the report* (was "unexplained").
2. **IOI clean/corrupt pairs are not token-length matched on this tokenizer.** CircuitKIT's own
   `tokenize_batch_pair` reports unequal clean/corrupt token counts (4 of 4 pairs in the first seed-0
   batch; 229 misaligned pairs over 101 batches) and 14 of 99 IOI names are multi-token; EAP aligns
   by end-padding, so for those pairs clean and corrupt activations are compared at shifted positions.
   This is the concrete reason the IOI circuit is weak (patching 0.02–0.20, random 0.24–0.30) and
   unstable on Tiny Aya; the brief's "neutral control" is a mis-specified task for this tokenizer, a
   finding about the toolkit's built-in task rather than about the model. The refusal pairs have the
   same defect for 45 of 207 pairs (third audit C8). *Documented*; IOI stays a bystander only.
3. **Grid driver.** `interventions/run_grid.py` gained the `*_joint` conditions and now reads the
   steering norm-match size from the saved `circuit` seed-0 cell instead of relying on loop order; the
   pre-registered conditions are untouched (`select.py` unchanged; `checks/check_lora_masks.py`
   28/28 still).
4. **Analysis.** `audit/analyze.py`: `pairs_for` (one pairing rule for all comparisons), `h1_text`,
   bootstrap p + Holm, the A15 section, pillar-mask L4 columns, trainable-parameter and node-overlap
   columns. Regression: the B2 tables regenerate with every previous number unchanged and the new
   sections appended.
5. **Tests and lint.** `uv run pytest -q` passes in all three repos (2 + 2 + 5); `ruff check` and
   `ruff format --check` clean.
6. **Determinism.** Unchanged from the third audit: MPS has no deterministic index_put kernel; steering
   cells reproduce bit-exactly, LoRA cells are not checked for bitwise equality; the A15 LoRA cells
   record `final_loss`, `n_trainable` and `mask_leak_max` (0.0) in their manifests.
